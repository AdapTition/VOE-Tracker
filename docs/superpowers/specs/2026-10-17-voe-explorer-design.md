# VOE Explorer — дизайн

Дата: 2026-10-17 · Статус: погоджено автором 2026-10-17

## 1. Навіщо

Офіційний сайт АТ «Вінницяобленерго» (voe.com.ua) незручний для двох повсякденних питань: «чому в мене зараз немає світла» і «коли його дадуть». Він погано розуміє адреси: щоб знайти `1-й пров. Ботанічний, 10`, треба вгадати, у якому вигляді сайт зберігає вулицю. А ще він часто лежить або відповідає дуже повільно.

VOE Explorer — це маленька десктопна програма для Windows. Користувач вводить адресу будинку звичними словами, а програма показує:

1. чи є зараз світло і чому його немає (аварія, черга ГПВ, планові роботи);
2. коли обіцяють увімкнути;
3. погодинний графік на сьогодні й наступні дні, якщо відключення планові.

Окремо програма стежить за самим сайтом VOE і показує, коли він лежав.

**Хто користуватиметься.** Автор; його батьки, для яких програма відкрита на окремому ноутбуці («підійшли й подивились»); друзі, яким автор скине exe. Батьки й друзі — не технічні люди.

## 2. Цілі

- Один `.exe` для Windows 10/11: без встановлення, без Python, без браузера. Скинув і запустив.
- Кілька збережених адрес. Кожна адреса показується окремою карткою з назвою, яку дав користувач («Батьки», «Я»).
- Пошук адреси, який розуміє довільне написання й ніколи не плутає вулицю з провулком, проїздом тощо (див. §6).
- Для кожної адреси: статус зараз, причина, час увімкнення, смужка на 24 години для кожного дня, який віддає VOE.
- Індикатор стану сайту VOE угорі. Натискання відкриває історію доступності та часу відповіді.
- Мінімалістичний, сучасний, приємний вигляд у стилі погодженого макета «A · Світлі картки» (§7).

## 3. Що не робимо

- Не робимо хостинг, сервер чи вебсайт: усе працює на машині користувача.
- Не робимо сповіщень, Telegram- чи Viber-бота, автозапуску з Windows. Автозапуск явно не потрібен.
- Не робимо пошуку за кодом EIC чи особовим рахунком: сайт таке вміє, але автор про це не просив.
- Не робимо версій для macOS і Linux.

## 4. Що вважатиметься провалом, навіть якщо «працює»

- Програма тихо підмінила адресу: користувач вводить «1-й пров. Ботанічний», а бачить статус вулиці Ботанічної чи 2-го провулку. Краще перепитати, ніж угадати не те.
- Програма показує «світло є», коли насправді не змогла отримати дані. Відсутність даних завжди видно явно, разом із часом останнього успішного оновлення.
- Час, коли програма була закрита, в історії доступності VOE показаний як «сайт лежав».
- Інтерфейс складний для батьків: дрібний текст, технічні терміни, коди помилок на екрані.
- Програма зависає або біла на 5–10 секунд, поки VOE відповідає. Усі запити йдуть у фоні, а інтерфейс лишається живим.

## 5. Що відомо про джерело даних (розвідка 2026-10-17)

Публічного API немає, готових проєктів на GitHub не знайдено. Але сайт сам ходить на публічні ендпойнти, і вони працюють без cookies, авторизації та капчі (reCAPTCHA на сторінці підключена, але ця форма її не вимагає). Повний ланцюжок перевірено з чистого Python (stdlib).

Скрипти розвідки: `docs/research/scripts/` (`probe.py` — повний ланцюжок адреса → графік).

**Платформа.** Drupal 10 за Cloudflare, `https://www.voe.com.ua`.

**Надійність.** У погані періоди кожен запит триває 5–8 с. Помітна частка відповідей — `502` з тілом `error code: 502` (Cloudflare), після чого повтор зазвичай проходить. Будь-який виклик потребує таймауту (~40 с) і кількох повторів з паузою.

### 5.1 Автокомпліт (GET, відповідь JSON)

| Крок | URL | Приклад |
|---|---|---|
| Місто | `/disconnection/detailed/autocomplete/read_city?q=<текст>` | `q=Він` → Вінниця, id `510100000` |
| Вулиця | `/disconnection/detailed/autocomplete/read_street/<city_id>?q=<текст>` | `q=Соборн` → `вулиця. Соборна`, id `1652` |
| Будинок | `/disconnection/detailed/autocomplete/read_house/<street_id>?q=<текст>` | `q=1` → `1`(26590), `10`, `101`, `11`, `12`, `12А`… |

Відповідь — це масив `[{"value": "...", "label": "<div class=\"change_api_autocomplit\" data-method=\"read_street\" data-id=\"1652\">...</div>"}]`, а id береться з `data-id` у `label`.

Формати `value`:
- місто: `м.. Вінниця (Вінницька Область/М.Вінниця)`, села `с.. …`;
- вулиця: `<тип>. [<номер>-й ]<Назва>`, наприклад `провулок. 1-й Ботанічний`, `проїзд. Ботанічний`, `вулиця. Юрія Смирнова/1 провулок Український`.

**Як сайт шукає вулиці.** Збіг перевіряється лише по частині після типу:
- `Ботан` → 6 результатів: вулиця Ботанічна, проїзд Ботанічний, провулок 1-й/2-й/3-й Ботанічний, провулок Ботанічний;
- `1-й Ботан` → 1 результат;
- `1 Ботан`, `пров. Ботан`, `провулок Ботан`, `Ботанічний пров` → 0 результатів.

**Пастка на Windows.** Кирилицю в `q` треба кодувати як UTF-8 (`urllib.parse.quote`). Неправильне кодування дає не помилку, а порожній список `[]`.

### 5.2 Графік для будинку (POST, Drupal AJAX)

1. `GET /disconnection/detailed`. З форми `#disconnection-detailed-search-form` взяти `form_build_id`.
2. `POST /disconnection/detailed?ajax_form=1&_wrapper_format=drupal_ajax`, `application/x-www-form-urlencoded`, поля:
   `search_type=0`, `city`, `city_id`, `street`, `street_id`, `house`, `house_id` (рядки `value` та id з автокомпліту), `form_build_id`, `form_id=disconnection_detailed_search_form`, `_triggering_element_name=search`, `_triggering_element_value=Показати`, `_drupal_ajax=1`.
3. Відповідь — масив AJAX-команд Drupal. HTML лежить у `data` команди з `"command": "insert"`.

Структура HTML у відповіді:
- `.disconnection-detailed-table-message`: текст для людини, наприклад «За Вашою адресою наразі не зафіксовано аварійних та планових відключень.»;
- `.disconnection-detailed-table-container`: 25 комірок-заголовків (`Часові проміжки`, `00-01` … `23-24`), далі для кожного дня одна комірка `legend day_col` (`сб 17.10`, поточний день має клас `current_day`) і 24 комірки `cell`;
- клас комірки задає стан. Побачено поки лише `no_disconnection`. Легенда на сторінці називає ще п'ять станів: підтверджене відключення (`cell-confirmed`), можливе (`cell-possible`), світло є (`cell-non-scheduled`), немає перші 30 хв (`cell-first-half`), немає другі 30 хв (`cell-second-half`). Чи збігаються ці назви з класами реальних комірок, **не перевірено**.

**Відповідь при реальному відключенні** (1-й пров. Ботанічний, 2, Вінниця, 2026-10-17, аварія). `.disconnection-detailed-table-message` містить:

```
<p>За вашою адресою в даний момент відсутня електроенергія</p>
<p>Причина відключення:  Аварійне відключення</p>
<p>Час початку – 09:16 2026.10.17</p>
<p>Орієнтовний час завершення – до 07:16 2026.10.18</p>
<p class="disconnection-message__warning">Увага! Наразі графіки погодинних відключень можуть не діяти. …</p>
```

**Важливо:** усі 24 комірки таблиці при цьому — `no_disconnection`. Таблиця відображає лише графік ГПВ, а аварійне відключення видно **тільки** з текстового повідомлення. Головним джерелом для «чому / коли» є повідомлення. Таблиця — джерело для «графіка». Між собою вони можуть суперечити, і це нормальний випадок, а не помилка (правило «гірше перемагає», §7).

Формати: причина йде після `Причина відключення:` (подвійний пробіл), час — у форматі `HH:MM YYYY.MM.DD`, кінець — з префіксом `до`. Інші причини (ГПВ, планові роботи) і текст, коли світло вимкнене за ГПВ, ще не бачили. Парсер має бути терпимим до невідомого тексту причини й показувати його як є.

Зразки сирих відповідей лежать у `docs/research/samples/`, скрипти розвідки — у `docs/research/scripts/`.

**Швидкість.** Того ж дня о ~10:30 запити йшли 5–8 с з частими 502, а о ~11:20 — 0.2–0.4 с без помилок. Сайт працює дуже нерівно, і саме це має бачити моніторинг (§8).

### 5.3 Аварійні відключення (GET, HTML)

`/disconnection` — HTML-таблиця з колонками `№ | РЕМ | Тип | Опис | початок | планове завершення | Населений пункт | Вулиця, будинок`. Приклад рядка: `Жмеринські ЕМ | Заходи обмеження | ГПВ Черга 2 Друга черга | 2022-11-08 15:00 | 2022-11-08 16:00 | ЖМЕРИНКА | вулиця Асмолова 1, 3, 9, 11-33…`.

**Сторінка мертва.** 2026-10-17 усі записи на ній датовані 2022-11-08: вона не оновлюється з 2022 року. Не використовувати.

### 5.4 Планові роботи (POST, звичайна форма)

`/disconnection/planned` — це форма `#disconnection-search-form` з полями `year` (`2026`), `month` (`01`…`12`), `region` (код РЕМ: `23` = Вінницькі МЕМ (місто), далі райони `25`…`57`, повний список у `<select name="region">`), необов'язковим `history=1`, а також `form_build_id`, `form_id=disconnection_search_form`, `op`. Відповідь — повна HTML-сторінка з таблицею:

`п/п | Тип відключення | Плановий час закінчення | Назва населеного пункту | Назва вулиць, перелік будинків | Статус | Початок відключення | Фактичний час закінчення | Час формування інформації | ID`

Приклад рядка: `Планове відключення | 2026-10-20 16:30:00 | ВІННИЦЯ | ВІННИЦЯ: вулиця Академіка Янгеля 40; вулиця Стрілецька 16,18,20,26,28,30 | Підтверджено | 2026-10-20 09:00:00 | | 2026-10-14 | 2826054`.

Вулиці відокремлені `;`, будинки — `,` (`83А`, `46/28`, `Н/У`, `ГАРАЖ`). Тип вулиці записаний повним словом без крапки, і бувають артефакти (`* 1-й Маріі Литвиненко-Вольгемут`, порожні `; ;`). Діапазонів (`11-33`) тут поки не бачили, але парсер має їх витримувати. Станом на 2026-10-17 для міста — 20 записів на 20–29.10. Сторінка жива.

**Важливо:** відповідь для будинку (§5.2) майбутніх планових робіт **не показує**. Для вул. Стрілецька, 16, де планові роботи 20.10, таблиця містить лише поточний день. Тож дізнатися про майбутні планові роботи можна тільки з цієї сторінки.

### 5.5 Що відбувалося 2026-10-17 (контекст зразків)

Після удару дрона значна частина Вінниці була без світла. Вибірка з 8 будинків (`docs/research/samples/2026-10-17_city-sample-summary.txt`) показала: у 5 — «Аварійне відключення» з різним часом початку (08:00, 09:16, 09:54) і завершенням «до» наступного ранку, у 3 — «не зафіксовано». В усіх таблицях усі 24 комірки — `no_disconnection`. Попередження VOE каже, що графіки ГПВ зараз можуть не діяти. **Відповіді з активними чергами ГПВ ми ще не бачили.**

**Як це працювало раніше (зі слів автора).** У 2025 і на початку 2026 року сайт працював стабільно, а черги ГПВ діяли. Таблиця показувала графік **на кілька днів наперед** (кілька рядків `day_col`) і **щодня змінювалась**, іноді всупереч тому, що показувала раніше. Офіційний сайт при цьому завжди показував актуальний варіант. Звідси вимоги:
- парсер розбирає довільну кількість днів;
- програма завжди показує останню отриману версію графіка й ніколи не «склеює» її зі старою;
- на картці видно, коли графік отримано («графік станом на 14:40»).

## 6. Пошук адреси

Це головна відмінність від сайту VOE.

**Розбір вводу.** Програма ділить те, що набрав користувач, на частини: тип вулиці, порядковий номер, корінь назви, будинок. Приклади, які мають працювати однаково: `1-й пров. Ботанічний, 10`, `1 провулок Ботанічний 10`, `перший Ботанічний провулок, 10`, `Ботанічний 1-й пров 10`.
- Словник синонімів типу: `вулиця/вул/вул.`, `провулок/пров/пров./пр-к`, `проїзд/пр-д`, `проспект/просп/пр-т`, `бульвар/бул/б-р`, `площа/пл`, `тупик/туп`, `узвіз`, `шосе`, `набережна`, `майдан`, `спуск`. Список має бути розширюваним.
- Порядковий номер розпізнається з `1`, `1-й`, `1й`, `перший`/`першій` тощо і зводиться до числа.
- Будинок нормалізується: латинські A/B/C/E… перетворюються на кириличні (`12A` → `12А`), регістр і пробіли прибираються, дроби й корпуси (`10/2`) зберігаються.
- Апострофи (`'`, `’`, `ʼ`) зводяться до одного.

**Запит до VOE.** На сайт іде лише корінь назви, і лише та частина, яку сайт гарантовано знайде (див. §5.1). Порядковий номер і тип у запит не потрапляють. Отримані кандидати розбираються тим самим парсером, що й ввід (`провулок. 1-й Ботанічний` → тип=провулок, номер=1, назва=Ботанічний).

**Як вибирається вулиця:**
- Тип, якщо його вказано, має збігатися точно. Номер, якщо його вказано, теж має збігатися точно.
- Якщо номер не вказано, а серед кандидатів є варіанти з номером і без, програма не вгадує: показує всі варіанти, і користувач вибирає.
- Автоматичний вибір можливий лише тоді, коли після фільтра лишився рівно один кандидат. В усіх інших випадках — короткий список варіантів для вибору. Вулиця й провулок ніколи не зливаються в один результат.

**Пам'ять.** Підтверджений вибір запам'ятовується: нормалізований ввід → (city_id, street_id, house_id, рядки `value`). Наступного разу той самий ввід не потребує запитів до сайту. Збережені адреси-картки зберігають ці id і не шукаються повторно.

**Місто.** Підтримується вся область, бо сайт це вміє. Вінниця пропонується за замовчуванням, але місто можна змінити. *Моє рішення.*

## 7. Інтерфейс

**Погоджений напрямок: «A · Світлі картки».** Макет: `voe explorer/.superpowers/brainstorm/187-1792224099/content/visual-style.html`, варіант A.

- Світлий теплий фон (~`#f6f6f3`), білі картки з ледь помітною тінню, системний шрифт (Segoe UI), багато повітря.
- Угорі назва та індикатор VOE: кольорова крапка й текст «VOE відповідає · 5.8 с», «VOE повільний» чи «VOE не відповідає». Натискання відкриває панель історії (§8).
- Картка адреси містить:
  - назву користувача (дрібно, сірим);
  - адресу (жирним);
  - рядок статусу, один із трьох станів (погоджено з автором):
    - `● Світло є` (зелений);
    - `● Немає світла · Аварійне відключення · до 07:16 завтра` (помаранчевий): повідомлення VOE «в даний момент відсутня електроенергія» або підтверджене відключення в поточну годину чи пів години за таблицею;
    - `● Можливе відключення` (жовтий): поточна година позначена як можлива або дані неоднозначні.
    Якщо джерела суперечать одне одному, перемагає гірший стан, а поруч дрібно вказано, звідки він узявся («за графіком» / «аварійне відключення»). «Світло є» показується лише тоді, коли всі доступні свіжі дані з цим згодні.
  - смужку з 24 годин для поточного дня. Кольори: підтверджене — помаранчевий, можливе — жовтий, половини години — половинка комірки, світло є — сірий. Інші дні VOE відкриваються з картки.
- Майбутні планові роботи. Якщо будинок картки є у списку планових робіт (§5.4) на найближчі дні, на картці з'являється рядок `🔧 Планові роботи · пн 20.10, 09:00–16:30`. Список береться для РЕМ, до якого належить місто картки, раз на кілька годин. Зіставлення йде тим самим парсером адрес (§6): тип, номер і назва вулиці, а також точний номер будинку. Якщо впевненого збігу немає, рядок не показується. *Моє рішення*, бо це прямо відповідає меті «графік, якщо це планове». Невирішене: як отримати код РЕМ для міста не з Вінниці. Може, з назви району в `value` міста, а якщо не вийде — для інших міст ця функція вимкнена.
- Пояснення кольорів (погоджено з автором): маленький значок «?» біля смужки або натискання на будь-яку кольорову комірку відкриває коротку легенду простими словами, наприклад «Жовтий — відключення можливе, але не підтверджене: світло може бути, а може й ні».
- **Сира відповідь сервера** (на прохання автора, щоб на перших порах бачити, як VOE насправді відповідає). У меню картки («⋯») є пункт «Відповідь VOE». Він відкриває панель з:
  - часом запиту, HTTP-кодом і тривалістю;
  - тим, як програма це зрозуміла: текст повідомлення, причина, початок і кінець, дні та стан кожної години, список невідомих класів комірок, якщо такі є;
  - сирим HTML з команди `insert` (з прокруткою й моноширинним шрифтом) та повним JSON-масивом AJAX-команд;
  - кнопками «Скопіювати» і «Зберегти у файл».

  Для кожної адреси зберігається остання відповідь, плюс останні N відповідей, у яких графік змінився. Пункт меню свідомо захований у «⋯», щоб не заважати батькам. Це саме стосується відповіді сторінки планових робіт (§5.4) і пробних запитів моніторингу (§8).
- Унизу «+ Додати адресу», далі пошук з §6.
- Картку можна перейменувати, перемістити, видалити.
- Батьки мають зрозуміти статус з першого погляду: великі контрасні слова для «є» / «немає», жодних технічних кодів.
- Якщо даних немає або вони застарілі: «Не вдалося оновити · останні дані о 14:40». Попередній графік лишається видно, але приглушено.
- Якщо VOE відповів, але відповідь не вдалося розібрати (змінилась структура сайту), це окремий стан, а не «немає даних»: «Сайт VOE змінився — потрібна нова версія програми». *Моє рішення.*

## 8. Моніторинг сайту VOE

- Поки програма відкрита, вона періодично робить легкий пробний запит до VOE і записує час, HTTP-код, тривалість і чи пусте тіло.
- Кожна спроба отримує стан: «відповідає», «повільно» або «не відповідає» (5xx, таймаут, мережева помилка). Звичайні оновлення карток теж пишуться в цю історію.
- Історія показує шкалу за день і за тиждень: коли сайт лежав, скільки це тривало, середній і найгірший час відповіді.
- Час, коли програма не працювала, показується як «немає даних» окремим кольором і ніколи не рахується як падіння (§4).
- Історія локальна, у кожної копії програми своя.
- Мережу самого користувача (немає інтернету взагалі) треба відрізняти від «VOE лежить». *Моє рішення:* перед тим як записати «VOE лежить», перевірити, чи доступний якийсь стабільний сторонній хост.

## 9. Невирішене, що треба з'ясувати на початку реалізації

1. ~~Відповідь з реальним відключенням~~ — **з'ясовано для аварії** (§5.2): причина й час є в текстовому повідомленні. Ще треба зловити: відключення за ГПВ (класи комірок `confirmed/possible/first-half/second-half` і чи пишеться черга) та планові роботи. Програма має сама зберігати сирі відповіді, які не вдалося повністю розібрати, у `%APPDATA%\VOE Explorer\samples\`, щоб нові формати можна було додати як фікстури.
2. ~~Чи потрібен `/disconnection`~~ — ні, сторінка мертва (§5.3).
3. **Як виглядають черги ГПВ.** Поки графіки не діють, побачити їх неможливо. Код розбору комірок спирається на назви з легенди (§5.2) і зберігає невідомі класи як зразки (п. 1). Коли ГПВ повернуться, перевірити й додати фікстури.
4. **Чи чутливий автокомпліт до регістру,** скільки символів мінімум і чи є ліміт на кількість результатів.

Вирішено разом з автором:

**Поширення (погоджено з автором):** без цифрового підпису, у zip-архіві. Запуск має бути простим, щоб «ніхто не парився». Мої рішення щодо цього:
- У zip лежать рівно два файли: `VOE Explorer.exe` (PyInstaller `--onefile --windowed`) і `Як запустити.png`. На картинці один крок: «якщо Windows показала синє вікно — натисніть "Докладніше" → "Усе одно запустити"». Один exe працює, навіть якщо його запустити прямо з архіву, не розпаковуючи.
- Якщо при першому запуску програма бачить, що вона лежить у тимчасовій папці чи в «Завантаженнях», вона пропонує одну кнопку: «Встановити на цей комп'ютер» — скопіювати себе в `%LOCALAPPDATA%\VOE Explorer\` і створити ярлик на робочому столі. Можна відмовитись.

**Оновлення (погоджено з автором: через GitHub, репозиторій закритий):**
- Код лежить у **приватному** репозиторії GitHub.
- Готові zip викладаються в **окремий публічний репозиторій тільки з релізами** (без коду і без опису, що рекламував би проєкт), наприклад `voe-explorer-releases`. Без прямого посилання його практично ніхто не знайде. *Моє рішення*, і ось чому: перевіряти релізи приватного репозиторію exe може лише з токеном доступу, а токен, вшитий в exe, дістане будь-хто, хто отримав файл. Тож вшивати токен не можна. Коли автор захоче відкрити код, приватний репозиторій просто стає публічним.
- При запуску (і не частіше ніж раз на добу) програма питає GitHub API про останній реліз публічного репозиторію релізів. Якщо версія новіша, з'являється ненав'язливий банер «Є нова версія» з посиланням на завантаження. Самооновлення немає: користувач завантажує новий zip сам. Якщо GitHub недоступний, програма мовчки працює далі.

Мої рішення (автор може змінити):
- Дані користувача (адреси, пам'ять пошуку, історія VOE, кеш останніх відповідей) лежать у `%APPDATA%\VOE Explorer\`. SQLite підходить для історії, JSON — для налаштувань.
- Картки оновлюються раз на 5 хв. Пробний запит до VOE — раз на 2 хв. Поріг «повільно» — понад 10 с.
- Python 3.12 на машині автора запускається через `py` (`python` у PATH немає).
- Логіку (парсер адрес, розбір HTML VOE, класифікацію стану сайту) покривають тести на збережених фікстурах, без живих запитів до VOE.
